WHAT DOES "SERVICES (BUSINESS LOGIC LAYER)" MEAN IN SPRING BOOT?
SPRING BOOT'TA "SERVICES (İŞ MANTIĞI KATMANI)" NE ANLAMA GELİR?
================================================================================

1. GENEL ANLAMI VE MİMARİDEKİ YERİ:
--------------------------------------------------------------------------------
Service katmanı, bir uygulamanın kalbidir. Controller (API) ile Repository (Veritabanı) 
arasında köprü görevi görür ve tüm iş kurallarını (Business Logic), veri doğrulama 
(Validation), güvenlik kontrollerini ve veri dönüşümlerini (DTO <-> Entity) yönetir.

Controller: Sadece HTTP isteklerini karşılar ve yanıt döner (Trafik polisi).
Service:    Tüm kararların alındığı, iş mantığının ve kuralların işlendiği yerdir.
Repository: Sadece veritabanı CRUD sorgularını çalıştırır.


2. INTERFACE SEGREGATION PRINCIPLE (ISP) VE MODÜLER ARAYÜZ YAPISI:
--------------------------------------------------------------------------------
Projede her servisin ihtiyaç duyduğu yetenekler küçük ve bağımsız arayüzlere bölünmüştür:

+----------------------------+-----------------------------------------------------+
| Interface                  | Sorumluluğu ve Metotları                            |
+----------------------------+-----------------------------------------------------+
| 1. ICrudService<D, E>      | Temel CRUD işlemleri:                               |
|                            | - objectServiceCreate, objectServiceList,           |
|                            | - objectServiceFindById, objectServiceUpdate,       |
|                            | - objectServiceDelete                               |
+----------------------------+-----------------------------------------------------+
| 2. ISortingPagingService   | Sayfalama ve sıralama:                              |
|                            | - objectServicePagination(currentPage, pageSize)    |
|                            | - objectServiceListSortedByAsc / Desc / ByDefault   |
+----------------------------+-----------------------------------------------------+
| 3. IImageService<D, E>     | Dosya ve görsel işleme:                             |
|                            | - objectServiceCreateWithFile                       |
|                            | - objectServiceUpdateWithFile                       |
+----------------------------+-----------------------------------------------------+
| 4. ISpeedAndDeleteService  | Hızlı test verisi üretme ve toplu veri silme:       |
|                            | - speedData(Integer data)                           |
|                            | - deleteData()                                      |
+----------------------------+-----------------------------------------------------+
| 5. IModelMapperService     | Veri transfer nesnesi ile Entity dönüşüm sözleşmesi:|
|                            | - entityToDto, dtoToEntity                          |
+----------------------------+-----------------------------------------------------+
| 6. IBlogServices           | Yukarıdaki tüm arayüzleri 'extends' ederek Blog     |
|    IBlogCategoryServices   | için tam donanımlı servis sözleşmesini oluşturur.   |
+----------------------------+-----------------------------------------------------+


3. BlogServicesImpl İÇERİSİNDEKİ KRİTİK METOTLAR VE İŞLEYİŞLERİ:
--------------------------------------------------------------------------------

A) speedData(Integer data) - Hızlı Mock Veri Üretimi:
   - `validatePositiveNumber(data, ...)` ile gelen sayının 0'dan büyük olduğunu doğrular.
   - İlişki Bütünlüğü (Referential Integrity): Bir blog KATEGORİSİZ var olamaz.
     Bu yüzden önce veritabanındaki ilk kategori aranır (`defaultBlogCategory`).
     Eğer hiç kategori yoksa `_404_NotFoundException` fırlatır ("Önce kategori açmalısınız").
   - `System.nanoTime()` kullanılarak her mock blog için benzersiz header oluşturulur.
   - İşlem bitiminde veriler küçükten büyüğe sıralı (`objectServiceListSortedByAsc`) döner.

B) deleteData() - İki Aşamalı Güvenli Temizlik (Disk + DB):
   - Klasik Hata: Sadece `deleteAll()` demek veritabanını temizler AMA yüklenmiş 
     tüm resimler sunucu diskinde çöp (Storage Leak) olarak kalır!
   - Çözümümüz:
     1. Aşama (Disk Temizliği): `iBlogRepository.findAll().forEach(b -> deleteImageSafely(b.getImage()))`
        ile fiziksel dosya sistemindeki resimler tek tek diskten silinir.
     2. Aşama (Veritabanı Temizliği): `iBlogRepository.deleteAll()` ile tablolar boşaltılır.
   - Geriye boş liste dönerek temizlik teyit edilir.

C) deleteImageSafely(String imageUrl) - Savunmacı Dosya Silme:
   - Resim URL'inin null olup olmadığını ve "/upload/" ile başlayıp başlamadığını denetler.
   - `imageService.deleteByUrl(imageUrl)` çağrısını try-catch içinde tutar. 
     Diskte dosya bulunamasa bile hata loglanır ama tüm veritabanı transaction'ı patlatılmaz.

D) objectServiceCreate & CreateWithFile:
   - `validate(blogDto, true)` ile zorunlu alanlar (header, content) denetlenir.
   - `validateBlogCategoryId(blogDto, true)` ile kategori ID'si doğrulanır ve kategori entity'si bağlanır.
   - Resimli create işleminde dosya önce `imageService.saveBlogImage(multipartFile)` ile diske 
     kaydedilir, dönen göreceli yol (`/upload/blog/...`) DTO'ya set edilir.

E) objectServiceUpdate & UpdateWithFile:
   - Mevcut blog entity'si `findBlogEntityById(id)` ile çekilir.
   - Başlık, içerik güncellenir; yeni resim gelmediyse eski resim yolu korunur.
   - Resimli güncellemede yeni dosya yüklendiğinde, eski resim diskten `deleteImageSafely(oldImageUrl)` 
     ile silinerek disk tasarrufu sağlanır.

F) Sayfalama ve Dinamik Sıralama:
   - `PageRequest.of(currentPage, pageSize, Sort.by(Sort.Direction.ASC, DEFAULT_SORT_FIELD))`
   - ASC, DESC ve istenen sütun adına göre (`validateNotBlank(sortedBy)`) dinamik sıralama yapılır.


4. İŞLEM YÖNETİMİ (@Transactional):
--------------------------------------------------------------------------------
1) Veri Değiştiren Metotlar (Create, Update, Delete, SpeedData):
   - `@Transactional` anotasyonu taşır. Herhangi bir aşamada hata fırlatılırsa 
     veritabanı otomatik olarak işlem öncesi durumuna ROLLBACK edilir.

2) Okuma Metotları (List, FindById, Pagination, Sorting):
   - `@Transactional(readOnly = true)` anotasyonu taşır.
   - Hibernate "dirty checking" mekanizmasını devre dışı bırakır, bellek ve 
     işlemci tasarrufu sağlayarak okuma sorgularını hızlandırır.
