================================================================================
WHAT DOES "BULK BATCH OPERATIONS" MEAN IN SPRING BOOT?
SPRING BOOT'TA "TOPLU İŞLEMLER (BULK BATCH OPERATIONS) MİMARİSİ" NE ANLAMA GELİR?
================================================================================

1. GENEL ANLAMI VE HEDEF:
--------------------------------------------------------------------------------
Kurumsal seviyedeki içerik yönetim ve e-ticaret platformlarında, yöneticilerin (Admin)
onlarca veya yüzlerce kaydı tek tek silmek, geri yüklemek veya kategorize etmek yerine
liste üzerinden seçerek tek bir operasyonda toplu işlem (Batch Action) yapabilmesi
büyük bir verimlilik sağlar.

Geleneksel Yaklaşım (Anti-pattern):
Döngü içinde tek tek `findById` ve `save` / `delete` çağırmak veritabanına N adet
ayrı sorgu gönderir (N+1 Sorgu Problemi), ağ gecikmesini (latency) katlar ve veritabanı
bağlantı havuzunu (HikariCP) kilitler.

Çözüm (Bulk Batch Mimari):
- Tek bir atomik SQL sorgusu ile onlarca kayıt tek seferde güncellenir/silinir:
  `UPDATE blogs SET ... WHERE blog_id IN (:ids)`
- N adet veritabanı gidiş-gelişi (roundtrip) tek bir ağ paketine indirgenir.
- Transactional bütünlük (`@Transactional`) sağlanır; hata durumunda tüm işlem geri alınır (Rollback).


2. TOPLU İŞLEM TÜRLERİ (`BulkActionType`):
--------------------------------------------------------------------------------
1) SOFT_DELETE:
   - Seçilen blogları fiziksel olarak silmez; `is_deleted = true, deleted_at = CURRENT_TIMESTAMP`
     yapar. Normal kullanıcılardan anında gizlenir, arşive taşınır.
   - SQL: `UPDATE blogs SET is_deleted = true, deleted_at = CURRENT_TIMESTAMP WHERE blog_id IN (:ids) AND is_deleted = false`

2) RESTORE:
   - Çöp kutusundaki (soft-deleted) seçili blogları kurtarır (`is_deleted = false, deleted_at = NULL`).
   - SQL: `UPDATE blogs SET is_deleted = false, deleted_at = NULL WHERE blog_id IN (:ids) AND is_deleted = true`

3) CHANGE_CATEGORY:
   - Seçili blogların tümünü hedef kategoriye (`targetCategoryId`) taşır.
   - Hedef kategorinin varlığı doğrulanır (`404 NotFoundException`).
   - SQL: `UPDATE blogs SET blog_category_id = :categoryId WHERE blog_id IN (:ids)`

4) ADD_TAG:
   - Seçilen tüm bloglara belirtilen etiketleri (`tags`) ekler.
   - Olmayan etiketler otomatik oluşturulur; Many-to-Many ilişkide tekrarlar engellenir.

5) HARD_DELETE:
   - Seçilen blogları ve ilişkili yorum/etiket kayıtlarını veritabanından kalıcı olarak temizler (`ON DELETE CASCADE`).
   - SQL: `DELETE FROM blogs WHERE blog_id IN (:ids)`


3. REST API VE UÇ NOKTA KULLANIMI:
--------------------------------------------------------------------------------
Endpoint: `POST /blog/api/v1.0.0/bulk`
Güvenlik: Yalnızca `ADMIN` ve `SUPER_ADMIN` rollerine açıktır (JWT Bearer Token zorunludur).

A) Toplu Soft Delete Örneği:
```json
{
  "blogIds": [1, 2, 3],
  "action": "SOFT_DELETE"
}
```

B) Toplu Kategori Değiştirme Örneği:
```json
{
  "blogIds": [4, 5],
  "action": "CHANGE_CATEGORY",
  "targetCategoryId": 2
}
```

C) Toplu Etiket Ekleme Örneği:
```json
{
  "blogIds": [1, 4],
  "action": "ADD_TAG",
  "tags": ["cloud", "devops"]
}
```

D) Yanıt Yapısı (`BulkOperationResponseDto`):
```json
{
  "status": "SUCCESS",
  "data": {
    "action": "SOFT_DELETE",
    "requestedCount": 3,
    "affectedCount": 3,
    "failedIds": [],
    "message": "3 adet blog başarıyla arşive taşındı (Soft Delete)."
  }
}
```


4. GÜVENLİK VE YETKİLENDİRME:
--------------------------------------------------------------------------------
- Anonim kullanıcılar ve `ROLE_USER` yetkisindeki standart üyeler bu uç noktaya erişemez (`401 Unauthorized` / `403 Forbidden`).
- `SecurityConfig` katmanında `POST /blog/api/v1.0.0/bulk` uç noktası `hasAnyRole("ADMIN", "SUPER_ADMIN")` ile korunmaktadır.
- Tek seferde en fazla 100 ID üzerinde işlem yapılabilir (`@Size(max = 100)` Bean Validation).
