================================================================================
WHAT DOES "CONFIG (WebMvcConfigurer)" MEAN IN SPRING BOOT?
SPRING BOOT'TA "CONFIG" YAPISI NE ANLAMA GELİR VE NELERİ YÖNETİR?
================================================================================

1. GENEL ANLAMI (Config Nedir?):
--------------------------------------------------------------------------------
"Config" (Configuration - Yapılandırma); uygulamanın çalışma zamanındaki genel 
davranışlarını, güvenlik kurallarını, dış dünya (Frontend) ile iletişimini 
ve web ayarlarını merkezi olarak belirlediğimiz kontrol merkezidir.

Spring Boot'ta bir sınıfın üzerine @Configuration yazdığımızda; Spring'e 
"Bu sınıf bir ayar merkezidir, uygulama başlarken buradaki kuralları oku ve uygula" 
demiş oluruz.


2. WebMvcConfigurer ARAYÜZÜ NEDİR?
--------------------------------------------------------------------------------
Spring Web MVC'nin varsayılan davranışlarını (CORS, Statik Dosyalar, Dil, Tarih vb.)
sıfırdan ezmeden, ihtiyacımıza göre özelleştirmemizi sağlayan ana arayüzdür.
WebConfig sınıfımız "implements WebMvcConfigurer" diyerek bu özelleştirmeleri yapar.


3. WebConfig.java İÇERİSİNDEKİ KRİTİK GÖREVLER VE TABLOSU:
--------------------------------------------------------------------------------
+--------------------------+----------------------------------------------------+
| Yapılandırılan Özellik   | Görevi ve Çözdüğü Problem                          |
+--------------------------+----------------------------------------------------+
| 1. CORS Yönetimi         | Frontend (React/Next.js) ile Backend'in tarayıcı  |
|    (addCorsMappings)     | engeline takılmadan haberleşmesini sağlar.         |
+--------------------------+----------------------------------------------------+
| 2. Statik Dosya Dağıtımı | Diske yüklenen resimlerin (Upload) HTTP linki      |
|    (addResourceHandlers) | olarak (/upload/**) tarayıcıda açılmasını sağlar.  |
+--------------------------+----------------------------------------------------+
| 3. Çoklu Dil (i18n)      | Kullanıcının dil tercihini Cookie'de saklar ve     |
|    (LocaleResolver)      | "?lang=tr" parametresiyle anlık dil değişimini     |
|                          | mümkün kılar.                                      |
+--------------------------+----------------------------------------------------+
| 4. Tarih Formatlama      | Frontend ile Backend arasındaki tarih formatını    |
|    (addFormatters)       | standart ("yyyy-MM-dd") hale getirir.              |
+--------------------------+----------------------------------------------------+


4. DETAYLI AÇIKLAMALAR:
--------------------------------------------------------------------------------

A) CORS (Cross-Origin Resource Sharing) Nedir?
   - Tarayıcılar güvenlik gereği farklı port veya alan adları arasındaki 
     istekleri varsayılan olarak BLOKE EDER (Same-Origin Policy).
   - Örneğin:
     Frontend : http://localhost:3000 (React / Next.js)
     Backend  : http://localhost:5555 (Spring Boot Projemiz)
   - Portlar farklı olduğu için tarayıcı isteği engeller.
   - WebConfig içindeki addCorsMappings() metodu ile:
     "http://localhost:* ve http://127.0.0.1:* üzerinden gelen GET, POST, PUT, 
     PATCH, DELETE isteklerine izin ver" diyerek iletişimin önünü açıyoruz.

B) Statik Dosya (Görsel / File Upload) Yayını:
   - Kullanıcı bir bloga resim yüklediğinde, bu dosya fiziksel olarak diske 
     (örn: ./upload/blog/2026/10/27/resim.png) kaydedilir.
   - Ancak dış dünyadaki bir tarayıcı doğrudan sunucunun diskine erişemez.
   - addResourceHandlers() metodu ile:
     "Gelen istek '/upload/**' ile başlıyorsa, bunu diskteki 'upload' klasöründen 
     oku ve kullanıcıya resim olarak sun" köprüsünü kuruyoruz.
   - CacheControl.noStore() ekleyerek görsel güncellendiğinde tarayıcının eski 
     görseli önbellekten (cache) göstermesini engelliyoruz.

C) Çoklu Dil Desteği (i18n - Internationalization):
   - LocaleResolver: Varsayılan sistem dilini Türkçe ("tr", "TR") olarak ayarlar 
     ve kullanıcının tercihini Cookie'de hatırlar.
   - LocaleChangeInterceptor: Kullanıcı URL sonuna "?lang=tr" veya "?lang=en" 
     yazdığında otomatik olarak ilgili dile (ValidationMessages.properties) geçer.

D) Standart Tarih Formatı:
   - addFormatters() ile tüm tarih alanlarının "yyyy-MM-dd" biçiminde ayrıştırılması 
     garanti altına alınır.


5. BİZİM PROJEMİZDEKİ UYGULANIŞI (com.berkeozder.config):
--------------------------------------------------------------------------------
Projenizde bu yapı şu dosyalardan oluşur:

1) WebConfig.java:
   - CORS, statik dosya köprüsü, dil çerezi ve tarih biçimlendirici ayarlarını 
     barındıran ana yapılandırma sınıfıdır.
   - FileProps nesnesini enjekte ederek upload dizininin yolunu dinamik okur.

2) RedisCacheConfig.java:
   - @EnableCaching ile Spring önbellek altyapısını aktifleştirir.
   - `spring.cache.type=redis` profilinde RedisCacheManager ve RedisTemplate yapılandırır.
   - Farklı önbellek anahtarları (categories, tags vb.) için özel TTL (Time-To-Live) tanımlar.
   - Redis bulunmayan ortamlarda otomatik fallback ile ConcurrentMapCacheManager sunar.

3) AsyncConfig.java (Adım 6):
   - @EnableAsync ile Spring asenkron görev havuzunu (ThreadPoolTaskExecutor) aktifleştirir.
   - Core Pool Size: 4, Max Pool Size: 10, Queue Capacity: 100 olarak yapılandırılmıştır.
   - E-posta gönderimi ve bildirimler HTTP istek iş parçacığını (Tomcat Thread) bloke etmeden
     arka planda "AsyncBlog-*" iş parçacıkları üzerinden tamamen asenkron yürütülür.

4) Observability & Actuator (Adım 9):
   - Spring Boot Actuator ve Micrometer Prometheus Registry entegrasyonu.
   - Endpoint'ler: `/actuator/health`, `/actuator/info`, `/actuator/metrics`, `/actuator/prometheus`.
   - JVM hafızası, CPU kullanımı, HikariCP veritabanı bağlantı havuzu, Tomcat aktif thread'leri ve
     HTTP istek süreleri (http.server.requests) Prometheus formatında dışa aktarılır.
   - SecurityConfig içerisinde actuator endpoint'leri beyaz listeye alınmıştır.

5) RateLimitConfig.java (Adım 10):
   - Token Bucket algoritması tabanlı hız sınırlama filtresini ve zamanlayıcıyı (@EnableScheduling) yapılandırır.
   - Brute-force ve DoS saldırılarını Bcrypt şifre çözümleme aşamasına gelmeden SecurityFilterChain'in en başında engeller.
   - FilterRegistrationBean ile servlet konteynerinin filtreyi iki kez çalıştırması önlenir.

6) Flyway Database Migration (Adım 11):
   - spring-boot-starter-flyway ve flyway-database-postgresql entegrasyonu.
   - SQL migrasyon betikleri: V1__init_schema.sql, V2__seed_roles_and_categories.sql, V3__add_performance_indexes.sql.
   - PostgreSQL üretim profilinde `spring.jpa.hibernate.ddl-auto=validate` olarak ayarlanır.

7) application.properties Entegrasyonu:
   - Sunucu portu: server.port=5555
   - Dosya yolu: file.upload-dir=upload
   - Dosya taban URL'i: file.base-url=http://localhost:5555
   - Whitelabel devre dışı: server.error.whitelabel.enabled=false
   - Cache türü: spring.cache.type=redis (postgres profilinde) / simple (dev & test)
