================================================================================
WHAT DOES "MINIO & S3 OBJECT STORAGE" MEAN IN SPRING BOOT?
SPRING BOOT'TA "MINIO / S3 UYUMLU CLOUD-NATIVE NESNE DEPOLAMA MİMARİSİ" NE ANLAMA GELİR?
================================================================================

1. GENEL ANLAMI VE HEDEF:
--------------------------------------------------------------------------------
Geleneksel web uygulamalarında kullanıcıların yüklediği resim ve dosyalar doğrudan
uygulama sunucusunun yerel diskine (Local Filesystem) kaydedilir. Ancak modern bulut
(Cloud-Native), mikroservis ve konteyner (Docker/Kubernetes) mimarilerinde:
- Sunucular Stateless (Durumsuz) olmalıdır: Container silindiğinde veya yeniden
  başlatıldığında yerel diskteki dosyalar kaybolmamalıdır.
- Yatay Ölçekleme (Horizontal Scaling): Birden fazla backend container'ı çalıştığında,
  birine yüklenen dosya diğer sunucularda bulunamaz.

Çözüm:
- Dosyalar container diski yerine AWS S3 uyumlu merkezi bir **Object Storage (Nesne Depolama)**
  üzerinde saklanır.
- Yerel geliştirmede ve şirket içi (On-Premise) ortamlarda AWS S3 API'si ile birebir uyumlu,
  açık kaynaklı ve ultra yüksek performanslı **MinIO** kullanılır.
- Strateji Deseni (Strategy Pattern) ile uygulama hem yerel disk (`storage.type=local`)
  hem de MinIO/S3 (`storage.type=minio`) üzerinde sıfır kod değişikliğiyle çalışabilir.


2. MİMARİ YAPISI VE STRATEJİ DESENİ (`FileStorageService`):
--------------------------------------------------------------------------------
A) `FileStorageService` (Arayüz):
   - `store(MultipartFile file, String module)`: Dosya boyutu, MIME tipi ve Magic Bytes
     imza kontrollerini yaptıktan sonra güvenle depolar.
   - `delete(String relativeUrl)`: Depolanan dosyayı siler.
   - `loadAsResource(String relativeUrl)`: Dosyayı `Resource` olarak istemciye iletir.
   - `getPresignedUrl(String relativeUrl)`: Doğrudan S3 üzerinden süreli, güvenli indirme URL'i üretir.
   - `getStorageType()`: Aktif stratejiyi döner (`LOCAL` veya `MINIO_S3`).

B) `FileStorageServiceImpl` (Yerel Disk Stratejisi):
   - `@ConditionalOnProperty(name = "storage.type", havingValue = "local", matchIfMissing = true)`
   - Geliştirme (`dev`) ve offline testlerde yerel `./upload` dizinini kullanır.

C) `MinioStorageServiceImpl` (MinIO / S3 Stratejisi):
   - `@ConditionalOnProperty(name = "storage.type", havingValue = "minio")`
   - Başlangıçta (`@PostConstruct`) bucket'ın varlığını kontrol eder (`bucketExists`),
     yoksa otomatik oluşturur (`makeBucket`).
   - `putObject` ile dosyaları S3 bucket'ına yükler: `/minio/{bucketName}/{module}/{year}/{month}/{day}/{uuid}.ext`.
   - `getPresignedObjectUrl` ile belirli süre geçerli (TTL) imzalı S3 bağlantısı sağlar.


3. DOCKER COMPOSE ENTEGRASYONU (`docker-compose.yml`):
--------------------------------------------------------------------------------
Sistem mimarisine `container_blog_minio` servisi eklenmiştir:
- Port 9000: MinIO S3 API erişim portu (Backend bu port üzerinden iletişim kurar).
- Port 9001: MinIO Web Konsolu (Yöneticiler tarayıcıdan bucket ve dosyaları görsel inceler).
- Kalıcı Hacim: `springboot2026_minio_data` named volume ile container silinse bile dosyalar korunur.
- Varsayılan Giriş: Kullanıcı: `minioadmin`, Şifre: `minioadmin`


4. REST API VE UÇ NOKTALAR (`StorageApiImpl`):
--------------------------------------------------------------------------------
Base URL: `/blog/api/v1.0.0/storage`

1) GET `/blog/api/v1.0.0/storage/info`
   - Aktif depolama motorunun durumunu döner (`LOCAL` veya `MINIO_S3`).
   - Örnek Yanıt:
     ```json
     {
       "status": "SUCCESS",
       "data": {
         "storageType": "LOCAL",
         "status": "ACTIVE"
       }
     }
     ```

2) GET `/blog/api/v1.0.0/storage/presigned?url=...`
   - İlgili dosya için güvenli, süreli doğrudan indirme bağlantısı (Presigned URL) üretir.

3) GET `/blog/api/v1.0.0/storage/download?url=...`
   - Dosyayı doğrudan HTTP akışı (Octet-Stream) olarak indirir veya görüntüler.


5. NASIL ÇALIŞTIRILIR?
--------------------------------------------------------------------------------
Seçenek 1: Docker Compose ile MinIO + Postgres + Redis + Backend
```sh
# 1) Tüm servisleri başlat
docker compose up -d

# 2) MinIO Web Konsoluna Eriş:
#    http://localhost:9001 (Kullanıcı: minioadmin / Şifre: minioadmin)

# 3) Bucket'ları incele:
#    'blog-bucket' otomatik oluşturulmuş ve yüklenen resimler burada saklanacaktır.
```

Seçenek 2: Yerel Geliştirme (Varsayılan Profil)
```sh
# Hiçbir Docker servisi olmadan yerel disk üzerinde hızlı geliştirme
mvn spring-boot:run
```
